# Архитектура и компоненты

Раздел «Архитектура и компоненты» должен описывать внутреннюю организацию MenshikovAI, основные модули и связи между ними. Правила оформления раздела:

- Описание необходимо начинать со схемы архитектуры, отображающей основные компоненты и связи между ними, после чего переходить к описанию назначения и взаимодействия отдельных компонентов.
- Для одного компонента необходимо использовать одно и то же название во всей документации.
- Названия модулей, классов, файлов и технических сущностей должны совпадать с фактическими названиями в проекте.
- Для каждого значимого компонента необходимо кратко указывать его назначение.
- Если компонент взаимодействует с другими частями системы, необходимо описывать направление такого взаимодействия.
- Архитектурное описание не должно превращаться в построчный разбор программного кода.
- Следует отделять описание пользовательского сценария от описания внутренней архитектуры.
- Если используется диаграмма, текст должен содержать краткое пояснение ее назначения.
- Диаграмма не должна быть единственным источником обязательной информации.
- После диаграммы рекомендуется кратко описать основные связи, показанные на ней.
- При описании внешних зависимостей необходимо указывать их роль в системе.
- Если архитектура изменяется, необходимо обновлять не только схему, но и связанное текстовое описание.
Для MenshikovAI к основным компонентам относятся Telegram-интерфейс, логика бота, модуль классификации интентов, модуль векторизации, набор данных и хранилище материалов.
