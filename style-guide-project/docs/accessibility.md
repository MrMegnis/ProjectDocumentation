# Доступность текста

Эти правила применяются ко всей технической документации проекта «Telegram-бот MenshikovAI».

## Заголовки

- Не допускается пропуск уровней заголовков. После заголовка первого уровня используется второй уровень, после второго — третий.
- Заголовок должен кратко и однозначно описывать содержание раздела.
- Не следует использовать слишком общие заголовки, например «Разное», «Дополнительно» или «Информация», если из них невозможно понять содержание раздела.

## Ссылки

- Текст ссылки должен описывать назначение перехода.
- Не допускаются формулировки «нажмите сюда», «по ссылке» или «здесь» без пояснения назначения ссылки.
- Если ссылка ведёт на внешний ресурс, из текста должно быть понятно, какая информация доступна по этому адресу.

## Изображения

- Изображение не должно быть единственным источником обязательной информации.
- Для значимых изображений необходимо добавлять краткое текстовое описание.
- Для изображений, размещаемых на сайте MkDocs, необходимо указывать альтернативный текст.
- Если изображение содержит важный результат, основной вывод необходимо также кратко описать в тексте документа.
- Каждый рисунок, таблица и листинг должны сопровождаться информативной подписью, которая кратко и однозначно отражает их содержание. Не допускаются слишком общие подписи, например «Схема», «Таблица» или «Пример кода», без уточнения назначения соответствующего элемента.

## Таблицы и списки

- Таблица используется только для сопоставимых данных.
- Для последовательности действий используется нумерованный список.
- Для независимых элементов используется маркированный список.
- Если в ячейках появляются несколько абзацев или вложенные списки, информацию следует разделить на отдельные блоки.
- Заголовки столбцов таблицы должны однозначно описывать содержащиеся в них данные.

## Ясность текста

- Один абзац должен раскрывать одну основную мысль.
- Сокращение необходимо расшифровать при первом употреблении, если оно не является общеизвестным для целевой аудитории.
- Необходимо избегать неопределённых формулировок, таких как «как обычно», «при необходимости», «если всё хорошо» и «стандартным способом».
- Для одного объекта во всей документации следует использовать одно и то же название.
- Инструкции необходимо формулировать через конкретное действие, например «Установите зависимости», «Запустите модуль», «Добавьте файл».
