# Как внести изменение в стайлгайд

## Предложить изменение

1. Проверьте действующие правила в `docs/` и навигацию в `mkdocs.yml`.
2. Создайте отдельную ветку от актуальной `main`.
3. Измените нужную страницу или добавьте новую. Сохраните согласованные названия разделов и файлов.
4. Локально проверьте сборку командой `mkdocs build --strict`.
5. Откройте Pull Request в `main`. В описании укажите, какие правила изменены, почему это нужно и как проверена сборка.

## Коммиты

Используйте формат Conventional Commits: `тип: краткое описание` или `тип(область): краткое описание`. Для документации подходит `docs`, для конфигурации сборки — `build` или `ci`, для исправления ошибки — `fix`. Например: `docs: add accessibility guidance`. Один коммит должен отражать одно логическое изменение.

## Ревью

Другой участник проверяет точность правил, согласованность терминов, работоспособность ссылок, соответствие навигации и результат сборки. Замечания обсуждаются в Pull Request. Автор вносит исправления отдельным коммитом и отвечает на комментарии. После одобрения и успешных проверок Pull Request сливается в `main`.

## Локальная сборка

Из корня репозитория перейдите в каталог проекта, создайте окружение, установите зависимости и проверьте сайт:

```bash
cd style-guide-project
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
mkdocs build --strict
mkdocs serve
```

Адрес локального сайта появится в выводе `mkdocs serve`. Каталог `site/` создаётся автоматически и не добавляется в репозиторий.

## Добавить раздел

1. Создайте файл `docs/<имя-раздела>.md` с одним заголовком первого уровня и правилами раздела.
2. Добавьте файл в `nav` файла `mkdocs.yml` под понятным читателю названием.
3. Убедитесь, что ссылки на новый раздел работают и `mkdocs build --strict` завершается успешно.
4. Опишите добавление раздела в Pull Request и дождитесь ревью.
